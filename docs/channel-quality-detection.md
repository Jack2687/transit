# 渠道题目降智检测

在「分组健康」顶部打开「降智检测配置」。配置仅属于当前用户、当前连接站点，其下已开启的分组共同使用。默认全局和分组均关闭。

1. 选择检测模型、推理强度和判断方式，编辑题目、答案、匹配方式及耗时阈值。
2. 在「检测配置」设置正常间隔、异常复测间隔、连续异常和恢复次数、并发及超时；启用并保存。
3. 在分组的「自动化策略」中勾选需要检测的渠道并保存，再打开左侧该分组的「降智检测」开关。后台仅检测已选择的渠道，关闭浏览器也继续执行。

降智检测复用自动化策略保存的渠道范围，包括分组策略和旧版渠道显式分配；分组内取消勾选的渠道不参与该分组的降智检测。降智检测是否运行仍由自己的全局和分组开关控制，不依赖健康策略的探活模型或启停状态。同一渠道在多个已开启分组中出现时，只要至少一个分组选择了它就检测一次。取消选择后，排队任务跳过检测，在途结果不再追加；已有历史保留。未选中渠道的卡片只显示名称、状态、手动探活和查看事件按钮，隐藏探活条、降智条及模型标签；重新选中后恢复详情。仅停用策略不会收起已选渠道。分组未开启降智检测时，已选渠道也不显示降智条。

在渠道卡片的「自动化」或「降智测试」下拉菜单中打开「渠道模型设置」，可分别设置探活模型和降智检测模型。默认勾选跟随配置：探活继承自动化策略中的模型，降智检测继承全局模型；取消勾选后填写该渠道支持的模型名称。保存对自动任务和手动测试同时生效，未加入自动化策略的渠道也可配置用于手动测试。改回跟随默认后会继续继承后续配置变更。

同一渠道在同一连接站点的多个分组中共享模型设置及检测记录，仍然去重检测一次。探活专用模型替换策略中的模型，沿用生效策略的探活方式、提示词、间隔、预算和暂停/恢复阈值，短期加权延迟及优先级判断也使用该模型；不修改共享策略。降智专用模型用于自定义题目和 API 糖果测试，API 鹈鹕仍按接口要求固定使用 `gpt-6-astra`。切换降智模型保留历史，重新累计连续判定次数；已有降智暂停仍需新结果达到恢复阈值才能解除，旧模型在途结果不会写入新配置的状态。

配置方式参考 Qerkai-sub2api 的题目检测。支持导入它的 JSON 题库与题目调度参数；不导入模型一致性或自动处理配置。导入后默认关闭，需确认并保存。

每轮每渠道执行一道已启用题目。标准答案允许纯答案或唯一的 `FINAL_ANSWER=` 行，也支持关键词和 Go 正则表达式。内容和耗时可单独或共同判断，耗时必须严格小于题目阈值，计时包含完整响应读取。有效答题后按题库顺序轮换；失败请求保留题目位置。

绿色表示本题通过，红色表示有效回答未满足规则，黄色表示检测请求失败。通过率仅统计有效答题。连续异常达到阈值才显示「降智」，连续通过达到恢复阈值才解除；网络、认证、限流、空响应和截断响应不累计答错次数。鼠标停在色块上可查看题目、实际答案、判断结果、耗时及时间。记录条按时间显示该渠道最近最多 100 次检测，包含之前配置下已完成的记录；修改配置、暂停或恢复不会隐藏已有记录，历史条的统计也以所展示的记录为准。

检测会使用渠道自己的上游凭据发送模型请求，复用现有渠道凭据解析能力；无法取得凭据或地址时显示检测失败，不伪造答题结果。OpenAI 使用 Responses，端点不存在时兼容 Chat Completions；Anthropic 和 Gemini 使用各自协议。只接受完整的最终文本回答，不允许工具调用。相同渠道被多个已开启分组覆盖时只检测一次。

结果独立存入 `connection_health_quality_*` 表。此功能不调用健康策略状态机、调权、暂停账号、切组或任何远端处理。修改配置会产生新版本，旧版本历史仍显示在记录条中，但不参与新配置的连续次数和当前降智判定；保存相同配置保留原版本与进度。保存结果时再次检查配置版本和分组开关，防止在途旧任务在关闭或修改后写入有效结果。每站点使用数据库租约防止多实例重复检测，站点并发可配置为 1～32，进程总并发不超过 32。

验证覆盖答案匹配、完成响应识别、计时、错误分类、轮换与连续次数、配置校验、作用域隔离、共享渠道去重、并发控制、配置变更及关闭后的旧结果拒绝。PostgreSQL 集成测试验证持久化、历史裁剪和无浏览器请求下的连续后台检测；页面通过隔离模拟接口验证，不开启真实渠道。
